# 写入、提交与失败恢复策略

本文定义未来分块写入和延迟写回的持久性契约。它是设计规范，不表示应用已经启用写回缓存。

## 不可破坏的约束

1. 文件系统写入返回成功时，对应字节必须已经在当前并发前置条件下被远端服务接受。
2. GugleFS 不得确认只存在于易失内存中的数据。
3. 无法证明远端仍是原版本时，自动恢复不得覆盖远端对象。
4. 恢复日志、缓存元数据、诊断和运行日志不得包含凭据、端点名称、用户名或明文远端路径。
5. 每个映射和整个进程使用的内存及本地暂存空间必须有界。

## 当前契约

当前 VFS 使用写穿语义。它按打开句柄串行写入，并等待 `RemoteFileSystem::write` 完成后才向 WinFsp 或 FUSE 返回成功。失败的句柄会拒绝后续写入，并让 `flush` 和 `release` 持续返回原错误类别。SFTP 直接写入指定范围，关闭远端写句柄后回读并逐字节校验该范围，截断后确认远端长度；FTP 读改写后先上传同目录非隐藏临时文件、校验远端长度，再重命名替换目标，以兼容禁止点号开头文件名的服务器；WebDAV 仍直接执行带条件的读改写。服务器提供版本信息时，WebDAV 使用 ETag 或 Last-Modified 作为并发前置条件。目前没有持久化本地写回日志。

在下述实施门槛全部满足前，写穿始终是默认行为。尤其是 WinFsp 的关闭处理无法在先前写入已经报告成功后可靠地返回后台上传的延迟错误。

## 计划中的分块模型

- 使用固定 4 MiB 逻辑分块，最后一个分块可以更短。
- 在分块内记录脏字节范围，避免小范围写入把未修改区域错误地置零。
- VFS 保持句柄内顺序，并在多个句柄之间使用每文件提交锁。
- 每映射最多保留 64 MiB 脏数据，整个进程最多 256 MiB；达到任一上限时对写入施加背压。
- 内存暂存作为快速路径。本地磁盘溢写必须由用户选择启用，使用系统安全凭据库中的随机密钥加密，以仅当前用户可访问的权限创建，并在提交或明确放弃后删除。

## 远端提交

首选事务会写入同目录临时对象，在协议允许时校验长度和摘要，再使用可用的最强重命名或移动原语替换目标。

| 后端 | 上传路径 | 并发保护 | 提交限制 |
| --- | --- | --- | --- |
| SFTP | 顺序写入同级临时文件 | 原始元数据及可选服务端扩展 | POSIX 重命名和服务端 `fsync` 扩展并非普遍可用 |
| WebDAV | `PUT` 到同级临时资源 | 强 ETag，否则使用 Last-Modified | 不同服务端对 `MOVE` 前置条件的支持不同，需要兼容性测试 |
| FTP/FTPS | 上传同级临时文件 | 在可用时比较大小和修改时间 | 重命名替换及原子性取决于服务器实现 |

如果后端无法证明目标仍是最初打开的版本，GugleFS 必须停止并返回冲突，恢复期间不得静默使用最后写入者覆盖语义。

## 日志与恢复

持久化恢复日志采用带版本的状态机：

`prepared -> uploading -> ready_to_commit -> committed -> cleanup`

每条记录只包含不透明的映射/文件事务 ID、分块编号、长度、摘要、远端版本校验器、时间戳和加密暂存文件引用。它不会包含配置使用的映射 ID、远端路径或任何秘密材料。

只有应用解锁且映射凭据可用后才开始恢复：

- `prepared` 或 `uploading`：只有能证明已上传分块身份和原远端版本时才继续，否则放弃临时对象并报告冲突。
- `ready_to_commit`：重新校验目标版本，然后只执行一次远端替换。
- `committed`：确认目标身份后再删除本地暂存数据。
- `cleanup`：重试删除本地和远端临时数据，不再修改目标。

日志转换使用本地新建临时文件、刷盘和原子重命名。损坏或版本未知的记录会被隔离，绝不自动重放。

## 实施门槛

只有以下条件全部满足后才能启用写回：

- 远端后端显式声明范围写入、条件替换、原子重命名、持久化刷写和对象身份能力。
- FTP、SFTP 和 WebDAV 集成测试覆盖上传中断、提交结果不确定、版本过期、重连和清理。
- WinFsp 和 FUSE 一致性测试在各自原生平台验证写入、刷写、关闭、进程崩溃、卸载和重新挂载结果。
- 挂载适配器能在操作系统把数据视为持久化之前返回最终提交错误，或界面让用户明确选择较弱的异步语义。
- 暂存加密、配额执行、日志迁移及恶意/损坏日志测试全部通过。

在此之前，GugleFS 保持写穿语义，并将协议相关的写入中断行为作为已记录的剩余风险。
